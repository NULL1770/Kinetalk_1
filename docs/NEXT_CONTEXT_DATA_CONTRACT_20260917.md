# 下一步连续上下文与数据覆盖契约

本文件为history12训练等待期间整理的工程方案，不修改当前数据锁，不表示扩大数据已经执行或一定有效。依据 `full_staged_data.py`、`neutral_data.native_clip` 和已完成的 `DYNAMIC_DATA_EXPANSION_PLAN_20260917.md` 库存审计。

当前2315 fit的完整native有效帧247,259，中央96帧实际曝光198,465，遗漏48,794（19.734%）。96帧仅3.84秒；历史8帧也仅0.32秒。native_clip先在有效帧至少32的窗口中选最接近中心的裁剪，并非所有短片都直接取几何中心。固定中央窗既遗漏动作起始/收尾，也让模型没有机会学习更长的表情准备与释放；这不证明被遗漏处一定包含可预测眉事件。

第一步只扩展**现有2315 fit clip**的时间覆盖，405内部开发和所有参考/封存角色保持。新建独立manifest记录clip、完整native hash、时钟、每epoch窗口起止、上下文halo和loss区间；不改旧锁或旧缓存。先做与原窗口重合的数值等价验证，再在fit中按长度选择固定的连续长短样本做前向/反向smoke。移动窗口需要同步移动motion、content、83维audio和其余音频特征；不能移动motion却复用仅覆盖中央窗的1540维特征。完整音频特征必须重新按原生时间提取或从可证时钟的完整源索引，并保留边界与padding mask。

独立neutral身份参考保持不变。B0/h0、audio global和local按新上下文重新编码；不复用旧窗口的已编码缓存。静态audio状态若由整句均值定义，需要显式说明离线全句条件，训练和部署保持一致；不得用目标motion全句均值构造条件。训练尺度只用fit。长序列padding、断检测gap、短历史、尾chunk和全句/分段接口应保持原始25Hz；不要把有效帧压缩后当连续时间。

先做同样更新步数的固定中央窗与移动/完整上下文配对，另报独特有效帧曝光和实际计算量。其后再单独研究八类与L2，不把时间覆盖、情感覆盖和模型部件一起改变。八类所需角色契约不仅是当前405：还必须合并旧280/439/audit26、enrollment和reserved等历史metadata曝光清单，按身份、句、录制明确排除后才可打开新增fit目标。native train库存不自动等于可训练池。

八类MEAD沿用原0–7标签，先保留现19 fit身份及三开发身份的隔离规则。重建query缓存、完整音频特征、fit统计尺度、训练采样记录与情感教师/学生监督；旧八logit分类器不代表曾训练过八类。记录每人/类/强度的独特时长及参考覆盖，按metadata预选每类原视频检查tracker。开发仍是内部开发，不能重新命名为未见测试。

CREMA-D单独后置：当前native_clip默认dataset_id=0、intensity_valid=True，直接用于其未知强度-1不正确。先建立真实dataset标识、unknown强度mask、六类映射与域分开评分，再决定是否混合。任何新实验都不因本契约而读取封存test目标。

若history12只改善oracle而generated历史无收益，优先定位生成前序的误差分布与训练/部署差异；若两臂都出现chunk边界尖峰，先处理共同分段生成机制。扩大上下文可作为独立对照，不能代替对本轮失败模式的解释。
