# 动态条件路径：分析与下一版设计

2026-09-17。根据用户澄清重新组织：问题是补齐成功方法中的条件表示、监督来源、生成机制与训练/推理路径，不能把用户的判断转述为“少一个loss”。本文是设计分析；没有启动新训练，也不把提案写成已验证效果。

后续用户要求具体收敛设计与跨模态可学习性：当前主基线与增量顺序已明确在`AUDIO_INTENSITY_BASELINE_DESIGN_20260917.md`。保留本文的三个条件角色作为完整架构范围；首版采用MED启发的显式强度+可学习融合，VA与详细运动state不同时堆入。

实施更新：用户已接受音频自动转写文本，当前首轮实施协议为`AUDIO_TEXT_DYNAMICS_PROTOCOL_20260917.md`；音频＋文本／无文本两臂各8epoch，原global先冻结，逐帧预测强度经过可学习融合进入renderer。窗口activity与生成history仍为后续增量，不应把本文的完整候选架构当作已实现。

## 三类变量应分开

1. **逐帧状态 s(t)**：表达的方向与当前程度。情感VA可描述愉悦/唤醒，但不能唯一决定抬眉/压眉；从系数计算的运动代理也不能冒称心理VA。初版可用少量有明确方向的上脸表达包络，区分眉抬起/下压、眼睁大/紧张等。按独立neutral参考及训练集尺度校准，保留持续姿态，不再逐query减时间均值。不能把整个52D GT包装成低维情感条件。
2. **窗口活动 a(w)**：本窗眉/眼运动变化的大小。持续皱眉可以状态强而活动小；弱表情可以叠加明显眉峰。使用有效帧上的区域时间变化统计，明确std的坐标、mask、尺度和观测置信度；眨眼事件与缓慢眼部情感变化宜分开统计，以免一次眨眼代表全部眼活动。
3. **动作历史 h**：前窗生成的姿态、趋势以及事件进行到哪一步。初版可以借鉴10帧context，但长度是待验证工程选择。训练初期可以GT history引导；后期必须接入生成history，推理仅用自己的历史，首窗有显式start/mask。

状态与activity需要分开定义，但不声称统计独立或已经解耦：状态随时间的变化本身会贡献窗口std。这里activity描述总运动量；若改为去状态后的高频活动，就是另一目标，必须预先固定频段和提取方法。状态方向可同时激活，不宜把抬眉减压眉压成一个会抵消的数。neutral校准使用独立参考的稳健均值和训练尺度下限，不除以接近零的个人std，也不重复叠加已有identity baseline。

强度标量只提供程度，不能凭自身区分压眉和抬眉。MEDTalk的标量配合情感embedding、内容及学习的decoder；把标量乘固定52D方向不是同一机制。也不能把MEAD L1/L2/L3广播为逐帧真值，或将情绪类别硬编码成VA后称为视觉连续监督。

## 最小完整路径

### 全局情感和motion→audio教导继续保留

上一版简图漏画了全局情感通路，现明确补上。历史pilot先联合训练motion teacher与renderer，再用teacher的global与local监督audio encoder；最新direct/output则复用冻结audio encoder产生的cached global/intensity，只训练新local与renderer，没有继续在线蒸馏。不能将“global仍输入生成器”与“本轮仍在更新global学生”混为一谈。

下一版继续保留`motion global teacher → audio global student → E_g → renderer`。教师提供训练期目标，推理仅用audio-global。第一阶段复用并冻结global以定位新增动态路径时，无需计算一个无可训练参数接收的蒸馏loss；若后续联合微调学生，则保留stop-gradient教师及类别/已知等级监督。局部教导改为明确的动态状态/activity目标及预测条件下的实际生成训练，不强制继续拟合旧的任意8D坐标。保留教师关系不意味着旧teacher权重永远冻结为唯一正确目标；数据范围或监督定义变化需重新核验教师。

总体优先借鉴SubtleTalk的条件残差生成，因为它与现有B0+flow分工接近；MEDTalk提供“有语义的动态表达条件必须经学习的decoder落到动作”的参照。不是把三篇所有模块同时叠上。逐帧状态的视觉VA与motion-derived方向状态是不同监督版本；先核验质量，再固定一个主版本，另一个可作对照。详细九方向状态是易核验的运动代理候选，不是声称复现了论文VA，也不能靠精确GT眉轨迹把问题变成复制输入。

```text
原始音频 → 内容特征 ────────────────────────→ B0 / content tokens
         → audio global student ────────────→ 全局情感 E_g
         → 多层声学＋绝对韵律 → 时序条件预测器 → 联合状态/活动条件、局部声学特征
独立中性参考 → identity ──────────────────────┐
前窗已生成动作 → history encoder ─────────────┼→ 同一全脸残差DiT → 最终动作
E_g、noise、s(t)、a(w)、局部声学、content ─────┘
```

训练期motion global teacher为audio global提供监督；真实motion/视觉读出为动态条件预测提供监督。E_g描述整段表达倾向，s(t)补充随时间的状态，activity约束窗口活动统计，history提供实际运动上下文。它们是不同用途的条件，不宣称相互独立或严格解耦；history尤其不是第三种情感变量。SubtleTalk把区域强度送入Global Condition Encoder，这个global指窗口共享条件，并不等于本项目的全局情感embedding。

新增的是条件和上下文，不是再建眉/眼/嘴三个独立解码器。继续保留一个52D输出。也不添加此前用户不采用的文本分支。

新的activity路径不沿用`1-p(neutral)`乘法开关。类别概率可以是条件，但中性不等于没有眉眼活动；无事件与低活动应由运动证据学习。

逐帧状态经专门projection加入对应帧context；窗口活动用独立embedding调制各DiT block；历史动作经带类型/位置/有效mask的context token进入注意力。三者不再全部挤进“去均值local”或`1-p(neutral)`。具体FiLM/adaLN/attention方案是实现选择，不能仅凭接口非零认定生成器利用正确。

保留直接局部声学通路，避免低维控制成为新瓶颈。音频预测负责可推断状态和活动分布，flow noise保留不确定的动作细节；不要求一个确定性头恢复每个随机眉峰。若采样活动，按窗口或连续时间过程采样，不逐帧独立抖动。

这里的状态/activity不应独立随意采样。可联合预测，或让activity分布显式依赖audio、global、预测state与可用history，保持条件组合一致。global与保留基线的state也会重叠；用分别固定/改变条件的干预验证职责，不以命名或强制正交冒充解耦。

完整原生时间轴、F0/voicing/energy以及多层特征必须重新对齐缓存；旧24bin、逐段中心化缓存不能恢复已丢弃的信息。先用现有fit做时序对照，再按历史排除规则扩MEAD八类/L2；不要同时改变数据、身份划分与模型然后归因一个模块。

跨窗使用一致的训练尺度和neutral参考，不每窗重新去均值或归一化而人为产生边界跳变。状态也可通过相同固定readout从最终生成动作读出以检查条件是否实现；不能只检查预测器数值或注入后的latent幅度。

## 训练与推理必须连起来

**阶段A：先确认监督可见和生成器会响应。** 固定训练样例检验原视频、拟合系数、rig的眉峰。用明确状态/activity条件训练接收这些变量的完整生成器，比较正常、固定、打乱、缩放条件及同noise输出。GT条件是训练/诊断oracle。状态条件如果携带接近完整眉轨迹，重建成功也只是信息充分的上限，不证明audio能预测。

旧oracle来自中心化残差的共享rank8投影；其方向、尺度、信息和入口不同，而且global仍为旧audio。旧oracle失败不能等价为新状态/activity/history也失败；同样也不能假定新oracle必定更好。

**阶段B：训练audio条件预测器并让预测条件参与生成。** 从真实motion/可靠视觉结果得到监督，训练audio→s(t)、a(w)分布。按训练句cross-fit生成预测条件，避免生成器只看到预测器记住训练样本后的过于准确输出。生成训练包含真实条件和预测条件，逐步以预测为主；全程保留纯audio分支的实际生成评价。历史同样从GT逐步过渡到前窗真实生成，不能只蒸馏latent后直接替换推理输入。

**阶段C：验证完整audio-only路径。** 推理不读query motion、GT activity、GT VA或未来真实history。先固定相同预算比较无显式状态/activity、增加状态、再增加activity，再验证history的跨窗连续性；完整方案形成后做必要消融。每个阶段先判断上一接口有无作用，避免一口气启动多套大训练。

VA值得借鉴，但现阶段没有经过核验的逐帧视觉VA数据。可先完成可靠的motion-derived状态/activity闭环；若加入VA，需独立说明视觉估计器、置信度与音频预测来源。它与区域运动条件互补，不必把所有条件强塞到第一版。

设计再审：若s(t)直接包含几乎完整的眉眼轨迹，其std已决定大部分activity，新增activity可能冗余，同时将任务转成音频回归运动。故九方向motion-state先作为强oracle/可解释代理对照，不锁定为最终主接口。更贴近SubtleTalk的主候选是粗粒度逐帧情感语义（可靠VA或有明确监督的动态表达embedding）+窗口活动+历史；motion-state版本需证明相对原音频直接预测的收益，再决定采用。三个角色有依据，但具体状态表示尚待对照确认。

## 论文对眉眼的专门处理与输出范围

MEDTalk官方`get_intensity`将8眉、4眼和2嘴角控制器汇总成逐帧单标量，使用最终174D输出的强度一致性与全rig重建。它关注眉眼，但不是眉/眼各自独立强度或独立decoder。

SubtleTalk用眉、眼区域FLAME顶点轨迹std形成两个独立窗口控制量，另有head XYZ三个；眉眼又分别参与区域velocity/std监督，IDC进一步训练改变某一活动控制时减小对其余部分的干扰。统一RFM输出全motion残差，而不是只生成眉眼。DMP也输出expression+jaw，非严格仅嘴；最终包括面部表情、jaw和head pose。

因此“动态”泛指随时间变化的动作，嘴部也属于动态；论文额外强调的是与语音不严格一一对应的眉眼/头部等细节。区域条件/区域监督不等于硬拆区域输出。当前52D ARKit路径没有独立head pose，不能把眉眼方案称为已经覆盖SubtleTalk全部动态范围。

## 生成器与训练预算的边界

MEDTalk的decoder先经过动作重建学习。当前完整renderer虽然已经开放训练，但来源与原数据覆盖有限，2×8epoch失败不能证明它已经学会对应的动作分布。新的条件接收能力要从训练样例拟合、验证响应与连续生成逐项确认；8epoch只作为短对照，不能自动视作充分收敛。若GT条件下就不能生成，应先定位motion表示、条件注入、初始化和优化，不继续只改audio predictor。

最终动作的范围与均值要在生成设计中处理，尤其52D残差仍能破坏嘴。不能只在显示阶段clip来掩盖问题，也不宜把嘴全部硬锁而丢掉情感嘴角。保留B0内容主路径，对最终嘴部允许的校正及系数域明确建模与验收；具体有界参数化需在新版本验证，避免随手后处理改变旧分布。

## 怎样判定各部分是否补对

| 结果 | 下一定位 |
|---|---|
| 明确GT状态/activity下仍无合理可见动态 | 先查表示、条件接收、生成器学习和输出域；audio预测不是唯一问题 |
| GT条件有效，audio预测条件无效 | 重点查声学信息、监督可靠性、预测泛化和训练/推理条件差异 |
| 单窗合理，跨窗断裂或逐渐漂移 | 查history训练、首窗、边界拼接与长序列漂移 |
| 幅度增加而时间/事件/分布不合理 | 查静态状态与活动混淆、模板/边界起伏、随机性；不按std单项通过 |

验收兼顾同noise音频错配/平移、activity改变的响应、多seed自然事件/分布、长序列连续画面以及最终嘴部/raw/mean输出。单GT相关只诊断可预测部分；不要求所有随机事件逐帧对齐，也不以强度可控冒充纯音频成功。
