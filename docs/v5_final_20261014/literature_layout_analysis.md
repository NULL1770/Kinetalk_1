# 文献编排分析与本稿对应关系

## 参考论文的写作逻辑

EmoTalk 的摘要和引言采用“任务背景—关键困难—方法机制—实验结论”的推进方式。其方法部分先给出完整生成路径，再分别解释内容/情感解耦编码器、情感引导融合解码器和训练损失；实验部分依次介绍数据与实现、评价指标、跨方法结果、定性结果、用户研究和组件消融。本文保留这种从问题到机制、从机制到证据的顺序，但把当前冻结 v5 的真实输入和已启用分支写清楚。

MEDTalk 的组织重点是解耦嵌入、动态情感和多模态控制。其主实验使用内容、情感和动态相关指标，交换实验用于证明控制变量的作用，消融实验与主要贡献逐项对应。本文借鉴其“条件交换先验证解耦，再报告生成质量”的证据组织，把文本从自动部署路径中移除，把动态写成音频条件事件过程，并单独说明 HDTF 没有统一情绪标签。

DiffPoseTalk 以 many-to-many speech-to-motion 问题引出说话风格，先定义风格，再报告 LVE、FDD、MOD、BA 和 diversity，并用用户研究和消融补充视觉证据。本文沿用“定义—指标—交换”的逻辑，不采用其扩散去噪解码器。Mimic 将个人风格落实为开合幅度、嘟嘴和速度等运动方式，并用 LDD/SCS 验证。当前 ARKit 开发协议暂时使用开合、速度、嘴宽和情绪保持代理；正式顶点拓扑对齐后再补 LDD/SCS。

## 正文表格

正文固定三张表，避免同一结果分散在多个旧表中。

1. **跨方法 ARKit 系数评价**：MBE、LBE 和 AbsFDD。比较 VOCA-core、FaceFormer、EmoTalk-core、FaceDiffuser 适配版本和 KineTalk-v5；当前冻结 v5 行必须按同一脚本补齐。
2. **跨方法网格运动评价**：LVE、EVE 和 vertex-FDD，统一角色绑定、顶点单位和区域掩码。
3. **KineTalk 组件消融**：围绕基座/情感输出、特权教师—学生、参考上下文与交换保持、因子交互/事件过程组织。没有同协议结果的格子标记待补，不用旧阶段数字替代。

## 术语边界

“中性发音基座”统一为 neutral articulation base；“特权教师—音频学生”统一为 privileged teacher–audio student；“条件化个人运动响应”统一为 conditional personal motion response；“音频条件事件过程”统一为 audio-conditioned event process。当前 v5 解码器是因子交互 TCN+Transformer 残差解码器，不写成 DiT 或 Flow Matching。教师只在训练期使用；文本不在自动部署路径中；HDTF 未标注情绪样本不参与情绪交叉熵。
