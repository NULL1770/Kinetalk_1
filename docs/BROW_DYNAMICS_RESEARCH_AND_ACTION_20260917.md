# 眉眼动态：本轮核查、实际补齐与后续路线

2026-09-17。范围为实际SSH内的v10继承链、容量对照、direct audio实验及本轮新output-motion实验。服务器、训练数据、源码、最终权重和原视频均已实际核查；本文不把旧v9/demo与新实验混报。

用户随后澄清：从未将失败归因为“少一个loss”，要求补齐成功方法中的逐帧情感/强度、窗口活动条件与前序动作上下文等机制。上一轮答复对此转述不准确。新的机制分析与最小完整训练/推理路线见`DYNAMIC_CONDITIONING_DESIGN_20260917.md`；它是设计方案，尚未启动新训练。

## 对目前效果和投稿的判断

**目前不建议以“细粒度眉眼情感动态已经解决、身份/口型/全局情感均可靠”为主张直接投稿。** CCF-C是会议/期刊分类，不是一个模型达到某个R²就自动满足的质量阈值。本项目已经有可复用的工程基础，但当前关键动态主张、完整消融、公平baseline和独立泛化证据尚不齐。

身份模块仅有4人独立neutral检索4/4的初步证据，表示的是动作偏置/执行统计，不是几何脸型。冻结B0后52维残差依然改变嘴部，本轮旧direct-L1在中性片段的最终嘴部raw MSE比来源增加67.6%。全局情感的高分多来自训练teacher读出或小样本分类，不是独立生成情感感知评价。这三部分可以作为基础，不能预先免检。

## 已完成的补齐，不能再重复建议

1. 历史大量rank8/尺度/小头/教师日程试验均已有失败记录；现有ridge眉预测统一增益接近其最佳可达误差，不能靠放大曲线解决。
2. 完整renderer的oracle/audio/zero容量对照已各完成8epoch，原flow仍失败；不能再把“从没训练完整生成器”当最新事实。
3. rich audio+完整renderer的flow vs flow+最终中心化L1已各完成8epoch。独立48组曲线重建一致：L1压制错误动态但眉仍不及own-zero、分布ES恶化且口型保护失败。详见`DIRECT_AUDIO_DYNAMICS_RESULTS_20260917.md`。
4. 本轮新建输出位移+std的audio/zero两臂，各8epoch/1160步；同数据、初值、优化器、batch/noise/time与来源hash，固定终轮，无checkpoint挑选。72组曲线独立重建全部一致：汇总中心化眉残差RMS达到GT的98.27%，相关却仅.033；这不代表逐片段幅度或显示后的眉动态恢复。相对matched-zero眉ΔR²=-.4099且CI全负，三个身份均退化。嘴动态变好但均值漂移导致raw误差增加，未采用。matched-zero仍保留B0/content/global的音频，只关闭新增local条件，因此该结果说明新增路径在本轮联合训练中没有净收益，不能解释为音频整体无用。见`OUTPUT_MOTION_DYNAMICS_RESULTS_20260917.md`。

## 数据扩展已核实为可执行方向

现有native TRAIN库存包括MEAD 12,959段/22人/15.7626有效小时，以及CREMA-D 5,797段/72人/4.0259小时。它们没有全部进入当前fit。当前2315条完整native本身有247,259有效帧，但固定crop只用198,465帧，另有48,794有效帧没见过。

仅排当前开发身份/句和enrollment后，有5,232条额外MEAD候选，其中fear892、surprise904；这只是库存审计，尚未完成所有历史开发/预留排除，不能直接当新训练manifest。CREMA的unknown intensity=-1必须mask，不能伪造零强度。

后续合理顺序是：

1. **先补数据/显示合同。** 用固定metadata样本验证原视频眉峰能否进入native系数，再确认GT rig可见。对负值裁剪分别报告raw与显示后动态；模型若有域偏移，需训练内校准输出均值/合法系数域，不靠后处理gain掩盖。
2. **重建实际声学训练缓存。** 保留完整时间序列与绝对韵律信息，在既有fit先比较固定窗口和确定seed的随机连续窗口；原24bin中心化缓存不能直接移动到新窗口。接着加入八类/L2，先维持当前19训练身份和全部历史保留角色。
3. **区分可预测事件与随机细节。** 保留一套全脸残差生成器，音频/韵律提供事件和窗口活动分布，noise提供条件下不确定细节。若借鉴眉眼区域强度控制，先给出推理可用的audio预测或明确用户控制协议；GT强度只作训练/oracle对照。确定性强度头不应要求恢复每个不可预测眉峰。
4. **训练完整可用路径后验证净收益。** 同预算audio与matched-zero训练；正确audio、反转/错配audio、固定多noise、逐人眉/眼/嘴、raw/mean/dynamic和ES/VS同时报告。std相等、负R²或单例好看都不是单独判据。通过开发后再用一次封存、身份和句子协议明确的最终测试。

这是有先后依赖的优化路线，不是保证“把别人某个loss抄上就成功”。已经测试的几种简单修法在各自固定预算下均未通过；当前仍有可核实的条件、数据和输出域缺口。

本轮最明确的可操作结论是：监督能改变汇总动态幅度，却没有同步改善条件分布或时序；完整输出的均值与系数域也不能继续放任。该固定预算不能定位唯一瓶颈，条件信息、上下文/监督、输出域和优化仍需分离验证，不能再以“上脸会动”作为唯一验收。

**还应明确区分“给活动条件”和“加幅度loss”**：SubtleTalk训练时将真实窗口眉眼std作为条件，当前方案只罚输出std，没有可靠的部署活动条件。可在下一套完整输出域保护下比较无活动条件、训练GT强度oracle、按训练句cross-fit的audio活动分布/强度三组；先确认oracle有效，再判断音频预测能否支持。GT条件不能进入audio-only正式评价；作者Table3推理强度来源未公开，不能默认其自动协议与我们等价。

std增大本身也不能证明随机细节恢复。下一次诊断需分开ensemble均值能量与seed间方差，检查跨片段曲线相似性、频谱、事件持续时间和窗口边界响应，并加入错配/平移音频。共同低频模板或边界起伏目前只是待检验假设。
